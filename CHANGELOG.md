## [Unreleased]

### Added
- The script policy of assistant scripts (ADR-036, P1 of the 2026-10-16 benchmark: F-R1, F-R2, F-R14; accepted in Revit 2026.3 on 2026-10-19 (add-in `faf2ce1`, read-only checks on a project template): Revit events, `PostCommand`, `OpenDocumentFile` and reflection refused before compilation in Python and C#, an event name built at run time refused by `getattr`, no `open` and no `System.IO`, the façade and typed tools working, `deferred_code_stopped` at 0). Scripts are `Agent` (`run_query`, `run_modify`, baked commands, `op: compile`) or `Shipped` (typed tools, audit presets: unchanged). Before compiling an assistant's Python script the add-in checks IronPython's syntax tree (`PythonPolicy`): Revit events (the Revit 2026 list plus those found by reflection on the loaded API), `PostCommand`, updaters, dockable panes, external events, opening, creating or copying documents, .NET reflection members, frame and code internals and double-underscore names outside a short list are refused as `PolicyError` (`not allowed in RIFT Python scripts: line N …`), nothing run; `op: compile` returns `type: PolicyError` and the server reports it. At run time `System` is a façade rebuilt for each run from a closed list of types (value types, maths, dates, conversions, collections, LINQ, text, regular expressions, cultures), standard-library modules are copies of their public names (without `codecs.open`, `operator.attrgetter`, frame walkers, code constructors), `open`, `input`, `breakpoint`, `help`, `exit` and `quit` are gone, `getattr`/`setattr`/`delattr`/`hasattr`/`vars` and `exec`/`eval`/`compile` apply the policy. Between runs a sentinel trace hook stops Python code a script left behind (an event handler, a callback) at its first line, counts it (`engine.deferred_code_stopped` in `get_context`) and logs where it came from. C# refuses the same Revit members (ADR-035). Server instructions describe the limits; `rift-mcp selftest` gains `deferred_code_refused` and `system_facade`. Tests: `ScriptPolicyTests`, C# member refusals (486 xUnit), `PolicyError` reporting (166 pytest).

### Fixed
- `SHA256SUMS.txt` (Stage): `tools/write_sha256sums.ps1` uses .NET calls only; Windows PowerShell started by MSBuild from a PowerShell 7 session (a developer's pwsh, the Windows CI runner) inherits a `PSModulePath` that breaks cmdlet autoloading, so the hashing step failed and the staged folder had no sums.
- `.gitignore`: the `runs/` rule (run journals) also matched the source folder `Rift.Scripting/Runs` on case-insensitive file systems, so `CompileOp`, `RunQueryOp`, `RunArgs`, `IRunHost` and `BlockedCalls` were never committed and a fresh clone did not build; the folder is now re-included and tracked.
- Server pipe client: `ERROR_PIPE_BUSY` reaches Python as `EINVAL` (C runtime) without `winerror`, so the 2 s busy retry never ran and a call made right after another one failed with `TARGET_LOST`.
- Discovery and key files: the atomic replace retries while a client holds the file open; a rotation could otherwise leave the old secret on disk.
