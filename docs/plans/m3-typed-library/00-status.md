# État : M3 — bibliothèque typée, vague 1

Jalon M3 de RIFT (ADR-013, ADR-026 §1, catalogue `docs/plans/tool-catalogue/`). Ouvert et codé le 2026-10-13 en autopilote (« boss sur RIFT jusqu'au produit fini »). Les quatre portes sont condensées ici parce que le périmètre était déjà arbitré : la liste des outils, leurs risques et leurs origines sont fixés par le registre depuis ADR-027 et ADR-030. **À valider par le mainteneur.**

## Porte 1 — Produit (rédigée 2026-10-13, autopilote)
- **Problème.** Avec M2, toute action passe par du code libre : l'assistant réécrit à chaque fois les mêmes scripts (lister les gabarits, appliquer un gabarit, renommer des types), avec les mêmes erreurs d'API, et chaque permission se joue sur un script illisible pour l'utilisateur.
- **Utilisateur.** Le BIM manager qui veut des actions nommées, prévisibles et autorisables une par une ; l'assistant qui veut des arguments typés plutôt qu'un script.
- **Critères.** (1) Les 50 outils typés du registre M3 répondent sur une copie SANDBOX avec des arguments en millimètres et en noms humains ; (2) chaque lecture est `auto` (aucune confirmation), chaque écriture passe par le chemin `run_modify` (SANDBOX, dry-run, une entrée Annuler, reçu) ; (3) `batch` enchaîne plusieurs écritures en une seule entrée Annuler ; (4) `survey` dit ce qu'un changement toucherait avant de le faire ; (5) la liste des permissions Claude Code se génère sans écriture dans `allow`.
- **Hors périmètre.** Création d'éléments de modèle, pièces, annotation, MEP, structure (ADR-027 §4) ; exports et cycle de vie du document (M4).

## Porte 2 — Architecture (rédigée 2026-10-13, autopilote) → ADR-032
Un outil typé = un script IronPython embarqué (`addin/src/Rift.Scripting/Tools/<nom>.py`) précédé d'un prélude commun (`_common.py`), déclaré lecture ou écriture par sa première ligne. Les lectures passent par le chemin de `run_query`, les écritures par celui de `run_modify`. Côté serveur, les arguments sont décrits une fois (`tools/typed.py`, `ARGS`) et l'outil MCP est construit à partir du registre.

## Porte 3 — Conception (rédigée 2026-10-13, autopilote)
- Add-in : `TypedToolCatalog` (ressources, en-tête, prélude), `TypedToolOp` (`IToolHandler`, `Serves`), `RunQueryOp.RunFixed(…, inputs, …)` et `RunFixedModify`, `rift_dry_run` pour les écritures hors modèle, `batch` (pilote Python exécutant les sources d'outils dans un seul run modify).
- Serveur : `typed.ARGS`, `signature()` (schéma d'entrée par `__signature__`), `call_typed`, `make_tool`, `read_result_ref` ; prompts `model_audit`, `pre_issue_check` ; ressource `rift://session/context`.
- Tests : catalogue = registre (51 scripts), compilation IronPython 3.4 de chaque script, imports autorisés, lecture sans transaction / écriture avec `tx()`, routage lecture/écriture/batch avec faux gardes ; côté serveur, schémas, envoi des `inputs`, arguments d'écriture, `result_ref` confiné au journal, prompts et ressource.

## Écarts et choix conservateurs
1. `create_project_parameter` crée un paramètre **partagé** via un fichier temporaire (l'API ne sait pas créer un paramètre de projet non partagé) ; il restaure le fichier de paramètres partagés en place.
2. `create_shared_parameter` écrit le fichier de paramètres partagés, hors maquette : en dry-run il ne fait que décrire (`would_create`), le garde ne pouvant pas annuler un fichier.
3. Les numéros de ligne d'erreur incluent le prélude (`TypedToolCatalog.PreludeLines` permet de les ramener au fichier de l'outil).
4. `purge_unused` dépend de `Document.GetUnusedElements` (Revit 2024+), refusé avec un message clair sinon.
5. Outils qui recoupent NORN FORGE et PRESS (feuilles, vues, mise en page) : seuls ceux déjà inscrits au registre M3 sont livrés ; le partage reste à arbitrer (ADR-030).
